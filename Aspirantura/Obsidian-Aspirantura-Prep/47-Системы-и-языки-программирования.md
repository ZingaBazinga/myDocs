# Вопрос 47. Системы и языки программирования. Машинно-ориентированные, проблемно-ориентированные и универсальные языки

← [[00-MOC-Aspirantura-Prep]] · Предыдущий: [[46-Разностные-методы-решения-нестационарных-задач-математической-физики]] · Программа: [[Вопросы#^q47|Вопросы]]

## Краткий ответ (для устного экзамена)

> [!abstract] Простыми словами — вся суть
> **Язык программирования** — формальная знаковая система для записи алгоритмов; задаётся алфавитом, синтаксисом и семантикой.
> **Система программирования** — комплекс средств: язык + транслятор + библиотеки + отладчик + среда разработки.
> **Три класса языков:**
>
> 1. **Машинно-ориентированные** (низкоуровневые) — ассемблер, машинный код: близки к «железу», максимальная эффективность, сложное программирование.
> 2. **Проблемно-ориентированные** (специализированные) — SQL, MATLAB, Fortran, HTML: заточены под конкретный класс задач.
> 3. **Универсальные** (общего назначения) — C, C++, Python, Java: решают широкий круг задач, баланс удобства и эффективности.
>    **Трансляция:** компилятор переводит всю программу в машинный код; интерпретатор исполняет построчно; JIT совмещает оба подхода.
>    Для математического моделирования выбирают язык по критериям: производительность, удобство, библиотеки, переносимость.

## Полный ответ

> [!abstract] Связный ответ комиссии
>
> **Определения.**
> Язык программирования — формализованная знаковая система для описания алгоритмов и структур данных, принимаемых машиной на исполнение.
> Три компонента языка: **алфавит** (допустимые символы), **синтаксис** (правила конструкций), **семантика** (смысл).
> Система программирования — комплекс средств, а не сам язык: язык + **транслятор** (компилятор/интерпретатор) + библиотеки + отладчик + IDE + **компоновщик**.
> Язык — правила записи; система — язык плюс инструменты разработки, трансляции, отладки и выполнения.
>
> **Уровень абстракции.**
> Машинный код → ассемблер → языки высокого уровня → сверхвысокоуровневые.
> Чем выше уровень, тем дальше от аппаратуры и тем больше работы берёт транслятор.
>
> **Классификация** (назначение и уровень абстракции — главный принцип).
>
> 1. **Машинно-ориентированные (низкоуровневые).**
>     Отражают архитектуру процессора: команды, регистры, адресация.
>     Машинный код — двоичные команды; ассемблер — мнемоники (`mov al, 61h`).
>     Плюсы: скорость, контроль, малый размер. Минусы: сложность, непереносимость (x86 и ARM — разные ассемблеры).
>     Применение: драйверы, ОС, встраиваемые системы, критичные по скорости участки.
>     Ассемблер не «устарел»: нужен прямой доступ к аппаратуре.
> 2. **Проблемно-ориентированные.**
>     Конструкции отражают предметную область: **SQL**, **MATLAB/R**, **Fortran**, HTML/CSS, COBOL, Prolog, Verilog/VHDL, LaTeX.
>     Удобны в своей области, вне неё почти неприменимы; это не языки общего назначения.
> 3. **Универсальные.**
>     **C**, **C++**, **Python**, Java, C#, JavaScript, Pascal/Delphi.
>     «Швейцарский нож»: широкий круг задач, компромисс по эффективности в узкой области.
>
> **Трансляция.**
> Транслятор переводит исходный текст в машинный код или промежуточное представление.
> **Компиляция** — весь код заранее (C, C++, Fortran): быстрый запуск, нужна перекомпиляция.
> **Интерпретация** — построчно (Python, Ruby): быстрее разработка, медленнее исполнение, один исходник.
> **JIT** (Java, C#) — байт-код + компиляция «на лету».
>
> **Этапы исполняемого файла:** исходный код → препроцессор → компилятор (объектный файл) → компоновщик → исполняемый файл.
> Без компоновщика объектные файлы программой не станут.
>
> **Выбор для моделирования (1.2.2):** производительность (C, C++, Fortran), удобство (Python), библиотеки (NumPy, SciPy, LAPACK), переносимость, визуализация, экосистема.
> Универсальный язык не всегда лучший.
>
> **Пример.** Связка Python + C++/Fortran: прототип на Python, тяжёлые ядра на C++/Fortran. MATLAB — интерактивные эксперименты.
>
> **Комиссии.** Три класса с примерами; язык ≠ система; компилятор ≠ интерпретатор; компоновщик обязателен; выбор языка — под вычислительный эксперимент.

## 1. Понятие языка программирования

### Определение

**Формулировка (учебник):** язык программирования — формализованная знаковая система, предназначенная для описания алгоритмов и структур данных, принимаемых вычислительной машиной на исполнение.

Язык задаётся тремя компонентами:

| Компонент     | Что определяет                 | Пример                            |
| ------------- | ------------------------------ | --------------------------------- |
| **Алфавит**   | допустимые символы             | латиница, цифры, `_`, `+`, `-`, … |
| **Синтаксис** | правила построения конструкций | `if (x > 0) { … }`                |
| **Семантика** | смысл (что делает конструкция) | условие выполняется при `x > 0`   |

> [!tip] Простыми словами
> Алфавит — «какие буквы», синтаксис — «как складывать слова в предложения», семантика — «что эти предложения значат».

### Уровни абстракции

$$
\text{машинный код} \;\to\; \text{ассемблер} \;\to\; \text{языки высокого уровня} \;\to\; \text{сверхвысокоуровневые}
$$

Чем выше уровень — тем дальше от «железа», тем проще писать, но тем больше работы делает транслятор.

## 2. Системы программирования

### Определение

**Формулировка (учебник):** система программирования — комплекс программных средств, обеспечивающий разработку, трансляцию, отладку и выполнение программ на определённом языке.

### Состав системы программирования

| Компонент                                 | Назначение                          |
| ----------------------------------------- | ----------------------------------- |
| Язык программирования                     | формальная запись алгоритмов        |
| **Транслятор** (компилятор/интерпретатор) | перевод исходного кода в машинный   |
| Библиотеки                                | готовые подпрограммы и модули       |
| Отладчик (debugger)                       | поиск и исправление ошибок          |
| Среда разработки (IDE)                    | редактор + инструменты в одном окне |
| Компоновщик (linker)                      | сборка модулей в исполняемый файл   |

### Этапы получения исполняемой программы (для компилируемых языков)

$$
\boxed{\text{Исходный код}} \;\xrightarrow{\text{препроцессор}}\;
\boxed{\text{Обработанный код}} \;\xrightarrow{\text{компилятор}}\;
\boxed{\text{Объектный файл}} \;\xrightarrow{\text{компоновщик}}\;
\boxed{\text{Исполняемый файл}}
$$

> [!tip] Простыми словами
> Пишем текст → препроцессор подставляет макросы → компилятор превращает в машинные команды → компоновщик склеивает с библиотеками → получаем готовую программу.

## 3. Классификация языков программирования

### 3.1. Машинно-ориентированные языки (низкоуровневые)

**Формулировка (учебник):** машинно-ориентированные языки отражают архитектуру конкретного процессора: набор команд, регистры, способы адресации.

#### Уровни

| Уровень      | Представление               | Пример              |
| ------------ | --------------------------- | ------------------- |
| Машинный код | двоичные команды процессора | `10110000 01100001` |
| Ассемблер    | мнемонические обозначения   | `mov al, 61h`       |

#### Характеристики

- **Зависят от архитектуры** (x86, ARM, MIPS — разные ассемблеры).
- **Плюсы:** максимальное быстродействие, минимальный размер кода, полный контроль над аппаратурой.
- **Минусы:** сложность, трудоёмкость, непереносимость, ошибки в адресации памяти.
- **Применение:** драйверы, ОС, встраиваемые системы, критичные по скорости участки.

> [!tip] Простыми словами
> Ассемблер — это «разговор с процессором на его языке». Быстро, но тяжело: каждая команда вручную, никаких абстракций.

### 3.2. Проблемно-ориентированные языки (специализированные)

**Формулировка (учебник):** проблемно-ориентированные языки предназначены для решения задач определённого класса; их конструкции отражают терминологию и структуру предметной области.

#### Примеры

| Язык               | Область применения                              |
| ------------------ | ----------------------------------------------- |
| **SQL**            | запросы к реляционным базам данных              |
| **HTML / CSS**     | структура и оформление веб-страниц              |
| **MATLAB / R**     | научные вычисления, статистика                  |
| **Fortran**        | численные расчёты, математическое моделирование |
| **COBOL**          | экономические и бизнес-приложения               |
| **Prolog**         | логическое программирование, ИИ                 |
| **Verilog / VHDL** | описание цифровых схем (аппаратуры)             |
| **LaTeX**          | вёрстка научных документов                      |

#### Характеристики

- **Плюсы:** удобство в своей области, короткие записи, встроенные операции.
- **Минусы:** неприменимы вне своей области, ограниченная универсальность.

> [!tip] Простыми словами
> SQL не умеет рисовать графики, а HTML не умеет считать интегралы — зато каждый из них делает «своё» лучше всех.

### 3.3. Универсальные языки (общего назначения)

**Формулировка (учебник):** универсальные языки предназначены для программирования широкого круга задач — от системного программирования до прикладных расчётов и веб-разработки.

#### Примеры

| Язык                | Особенности                                                      |
| ------------------- | ---------------------------------------------------------------- |
| **C**               | системное программирование, близость к аппаратуре                |
| **C++**             | C + ООП, обобщённое программирование, высокая производительность |
| **Python**          | простота, читаемость, богатые библиотеки (NumPy, SciPy)          |
| **Java**            | платформонезависимость (JVM), ООП                                |
| **C#**              | .NET-экосистема, ООП                                             |
| **JavaScript**      | веб, клиентская и серверная разработка                           |
| **Pascal / Delphi** | обучение, прикладные программы                                   |

#### Характеристики

- **Плюсы:** универсальность, переносимость, развитые библиотеки.
- **Минусы:** компромисс — не всегда максимальная эффективность в конкретной области.

> [!tip] Простыми словами
> Универсальный язык — «швейцарский нож»: можно сделать всё, но не всегда так же быстро или удобно, как специализированным инструментом.

## 4. Сравнительная таблица трёх классов

| Критерий                   | Машинно-ориентированные | Проблемно-ориентированные | Универсальные        |
| -------------------------- | ----------------------- | ------------------------- | -------------------- |
| Уровень абстракции         | низкий                  | средний/высокий           | высокий              |
| Зависимость от архитектуры | сильная                 | слабая/нет                | слабая/нет           |
| Область применения         | управление «железом»    | конкретный класс задач    | широкий круг задач   |
| Производительность         | максимальная            | зависит от области        | хорошая/высокая      |
| Сложность освоения         | высокая                 | средняя                   | средняя/низкая       |
| Примеры                    | ассемблер x86, ARM      | SQL, MATLAB, Fortran      | C, C++, Python, Java |

> [!important] На экзамене
> Главный принцип классификации — **назначение и уровень абстракции**:
>
> - машинно-ориентированные → «ближе к процессору»;
> - проблемно-ориентированные → «ближе к предметной области»;
> - универсальные → «для всего».

## 5. Трансляция: компиляция и интерпретация

### Определения

**Формулировка (учебник):** транслятор — программа, преобразующая исходный текст на языке программирования в машинный код или промежуточное представление.

| Вид трансляции      | Принцип работы                                       | Примеры языков  |
| ------------------- | ---------------------------------------------------- | --------------- |
| **Компиляция**      | весь код переводится в машинный заранее              | C, C++, Fortran |
| **Интерпретация**   | построчное исполнение без предварительной трансляции | Python, Ruby    |
| **Смешанная (JIT)** | компиляция в байт-код + JIT-компиляция «на лету»     | Java, C#        |

### Схема компиляции

$$
\text{Исходный код (C++)} \xrightarrow{\text{компилятор}} \text{объектный код} \xrightarrow{\text{линкер}} \text{исполняемый файл (.exe)}
$$

### Схема интерпретации

$$
\text{Исходный код (Python)} \xrightarrow{\text{интерпретатор}} \text{непосредственное исполнение}
$$

### Сравнение

| Критерий            | Компиляция                 | Интерпретация          |
| ------------------- | -------------------------- | ---------------------- |
| Скорость исполнения | высокая                    | ниже                   |
| Скорость разработки | медленнее (перекомпиляция) | быстрее (запуск сразу) |
| Отладка             | сложнее                    | проще                  |
| Переносимость       | нужен новый бинарник       | один и тот же код      |
| Пример              | C++, Fortran               | Python                 |

> [!tip] Простыми словами
> Компилятор — переводчик книги целиком: один раз перевёл, потом читают быстро. Интерпретатор — синхронный переводчик: переводит на лету, но медленнее.

## 6. Критерии выбора языка для математического моделирования

Для специальности 1.2.2 (математическое моделирование, численные методы) язык выбирают по:

| Критерий               | Что важно                                                 |
| ---------------------- | --------------------------------------------------------- |
| **Производительность** | скорость расчётов (C, C++, Fortran)                       |
| **Удобство**           | прототипирование, читаемость (Python)                     |
| **Библиотеки**         | численные методы, линейная алгебра (NumPy, SciPy, LAPACK) |
| **Переносимость**      | работа на разных платформах                               |
| **Визуализация**       | построение графиков и диаграмм                            |
| **Экосистема**         | интеграция с другими инструментами                        |

### Типичные связки в научном моделировании

- **Python + NumPy/SciPy** — прототипирование и расчёты.
- **C++/Fortran** — высокопроизводительные ядра расчётов.
- **MATLAB** — интерактивные численные эксперименты.
- **Python + C++** — гибрид: удобство Python, скорость C++.

> [!tip] Простыми словами
> В науке часто пишут прототип на Python, а самые тяжёлые вычисления переносят в C++/Fortran и вызывают из Python — получают и удобство, и скорость.

## 7. Типичные ошибки на экзамене

> [!failure] Частые ошибки
> Путать **язык** (правила записи) и **систему программирования** (язык + транслятор + библиотеки + отладчик).
> Считать ассемблер «устаревшим» — он незаменим там, где нужен прямой доступ к аппаратуре.
> Называть SQL или HTML «языками программирования общего назначения» — они проблемно-ориентированные.
> Путать компилятор и интерпретатор: компилятор переводит заранее, интерпретатор исполняет сразу.
> Забывать про компоновщик (linker) — без него объектные файлы не станут программой.
> Утверждать, что универсальный язык всегда лучше: выбор зависит от задачи.
> Не приводить примеры из каждой категории — без примеров ответ «пустой».

### 3. Машинно-ориентированные vs универсальные

- [x] Чем машинно-ориентированные языки отличаются от универсальных?

**Ответ.** Машинно-ориентированные (ассемблер, машинный код) отражают архитектуру процессора: максимальная скорость и контроль, сильная зависимость от «железа», сложность, непереносимость. Универсальные (C, C++, Python, Java) — высокий уровень, широкий круг задач, переносимость, компромисс по эффективности. Классификация: ближе к процессору vs для всего.

---

### 4. Проблемно-ориентированные языки

- [x] Приведите примеры проблемно-ориентированных языков.

**Ответ.** Языки под класс задач, конструкции отражают предметную область: **SQL** (БД), **MATLAB/R** (расчёты, статистика), **Fortran** (численные расчёты), **HTML/CSS** (веб), COBOL, Prolog, Verilog/VHDL, LaTeX. Удобны в своей области, вне неё почти неприменимы. Не языки общего назначения.

---

### 5. Универсальные языки

- [x] Приведите примеры универсальных языков программирования.

**Ответ.** C (системное, близко к аппаратуре), **C++** (C + ООП, производительность), **Python** (простота, NumPy/SciPy), Java (JVM), C#, JavaScript, Pascal/Delphi. «Швейцарский нож»: можно всё, но не всегда так же удобно, как специализированным языком.

---

### 6. Компилятор и интерпретатор

- [x] В чём разница между компилятором и интерпретатором?

**Ответ.** **Компиляция** — весь код заранее в машинный (C, C++, Fortran): быстрый запуск, нужна перекомпиляция. **Интерпретация** — построчное исполнение (Python, Ruby): быстрее разработка, медленнее исполнение, один и тот же исходник. **JIT** (Java, C#) — байт-код + компиляция «на лету».

---

### 7. Этапы получения исполняемого файла

- [x] Назовите этапы получения исполняемого файла из исходного кода.

**Ответ.** Для компилируемых языков:
$$
\text{исходный код}\xrightarrow{\text{препроцессор}}\text{обработанный код}\xrightarrow{\text{компилятор}}\text{объектный файл}\xrightarrow{\text{компоновщик}}\text{исполняемый файл}.
$$
Без компоновщика объектные файлы программой не станут.

---

### 8. Критерии выбора языка

- [x] Каковы критерии выбора языка для математического моделирования?

**Ответ.** Производительность (C, C++, Fortran); удобство прототипирования (Python); библиотеки (NumPy, SciPy, LAPACK); переносимость; визуализация; экосистема. Выбор зависит от задачи, универсальный язык не всегда лучший.

---

### 9. Связка Python + C++

- [x] Почему Python часто используют в связке с C++ в научных расчётах?

**Ответ.** Python — прототип, читаемость, библиотеки; C++/Fortran — тяжёлые ядра. Гибрид: удобство Python + скорость C++ (вызов оптимизированного кода из высокоуровневой среды).

---

### 10. Ассемблер

- [x] Что такое ассемблер и где он применяется?

**Ответ.** Низкоуровневый язык: мнемоники команд процессора (`mov al, 61h`) вместо двоичного кода. Зависит от архитектуры (x86, ARM). Применение: драйверы, ОС, встраиваемые системы, критичные по скорости участки. Не «устарел»: нужен прямой доступ к аппаратуре.

# Вопрос 51. Прикладное программное обеспечение математического моделирования. Математические библиотеки, пакеты прикладных программ

← [[00-MOC-Aspirantura-Prep]] · Предыдущий: [[50-Основы-объектно-ориентированного-программирования]] · Программа: [[Вопросы]]

## Краткий ответ (для устного экзамена)

> [!abstract] Простыми словами — вся суть
> **Прикладное ПО математического моделирования** — программы и программные комплексы для реализации математических моделей: от библиотек численных методов до готовых пакетов моделирования.
> **Математические библиотеки** — наборы подпрограмм для типовых вычислительных операций: BLAS/LAPACK (линейная алгебра), FFTW (БПФ), QUADPACK (интегрирование), ODEPACK (ОДУ).
> **Пакеты прикладных программ (ППП)** — готовые среды для моделирования: MATLAB, Mathematica, Python (NumPy/SciPy), Julia.
> **Различие:** библиотека — «кирпичики» для встраивания в свой код; пакет — «готовый инструмент» с интерфейсом.
> **Критерии выбора:** точность, производительность, надёжность, документация, лицензия.
> В численных методах: решение СЛАУ через LAPACK, интегрирование ОДУ через SciPy, разностные схемы через NumPy.
> **Верификация и валидация** — обязательные этапы работы с ППО моделирования.

---

## 1. Понятие прикладного программного обеспечения математического моделирования

### Определение

**Формулировка (учебник):** прикладное программное обеспечение (ППО) математического моделирования — совокупность программных средств, предназначенных для реализации математических моделей, проведения вычислительных экспериментов и анализа результатов.

### Место в иерархии ПО

| Уровень                         | Примеры                      | Назначение               |
| ------------------------------- | ---------------------------- | ------------------------ |
| **Системное ПО**                | ОС, драйверы                 | управление аппаратурой   |
| **Инструментальное ПО**         | компиляторы, IDE             | разработка программ      |
| **Прикладное ПО моделирования** | MATLAB, ANSYS, библиотеки ЧМ | решение прикладных задач |

### Задачи ППО моделирования

| Задача                                  | Пример                           |
| --------------------------------------- | -------------------------------- |
| Реализация численных методов            | решение СЛАУ, интегрирование ОДУ |
| Проведение вычислительного эксперимента | расчёт эволюции решения          |
| Визуализация результатов                | графики, поля, анимация          |

> [!tip] Простыми словами
> ППО моделирования — «инструменты для численного эксперимента»: от готовых функций до целых сред, где можно задать модель, посчитать и увидеть результат.

## 2. Классификация ППО математического моделирования

### Основные группы

| Группа                                  | Характеристика                     | Примеры                               |
| --------------------------------------- | ---------------------------------- | ------------------------------------- |
| **Математические библиотеки**           | наборы подпрограмм для встраивания | BLAS, LAPACK, SciPy                   |
| **Пакеты прикладных программ**          | готовые среды с интерфейсом        | MATLAB, Mathematica                   |
| **Системы компьютерной алгебры**        | символьные вычисления              | Maple, SymPy                          |
| **Среды моделирования**                 | визуальное моделирование           | Simulink, COMSOL                      |
| **Проблемно-ориентированные комплексы** | для конкретной области             | ANSYS (механика), SPICE (электроника) |

> [!important] На экзамене
> Библиотека — «полуфабрикат»: встраивается в вашу программу. Пакет — «готовое блюдо»: используется как самостоятельный инструмент.

## 3. Математические библиотеки

### Определение

**Формулировка (учебник):** математическая библиотека — коллекция реализованных и отлаженных подпрограмм (функций, процедур) для выполнения типовых численных операций, предназначенная для использования в других программах.

### Основные библиотеки

| Библиотека      | Область                            | Язык      |
| --------------- | ---------------------------------- | --------- |
| **BLAS**        | базовые операции линейной алгебры  | Fortran   |
| **LAPACK**      | решение СЛАУ, собственные значения | Fortran   |
| **FFTW**        | быстрое преобразование Фурье       | C         |
| **QUADPACK**    | численное интегрирование           | Fortran   |
| **ODEPACK**     | решение систем ОДУ                 | Fortran   |
| **SparseSuite** | разреженные матрицы                | C         |
| **PETSc**       | параллельные численные методы      | C/Fortran |
| **Intel MKL**   | оптимизированные мат. операции     | C/Fortran |
| **OpenBLAS**    | открытая реализация BLAS           | Fortran/C |

### Библиотеки в экосистеме Python

| Библиотека     | Назначение                                               |
| -------------- | -------------------------------------------------------- |
| **NumPy**      | массивы, базовые операции                                |
| **SciPy**      | численные методы: интегрирование, оптимизация, СЛАУ, ОДУ |
| **SymPy**      | символьные вычисления                                    |
| **Matplotlib** | визуализация                                             |
| **Pandas**     | обработка данных                                         |

### Примеры вызовов

**Решение СЛАУ через LAPACK/NumPy:**

```python
import numpy as np
A = np.array([[2, 1], [1, 3]])
b = np.array([5, 7])
x = np.linalg.solve(A, b)   # внутри — LAPACK
```

**Интегрирование ОДУ через SciPy:**

```python
from scipy.integrate import solve_ivp
sol = solve_ivp(fun, t_span, y0, method='RK45')
```

> [!tip] Простыми словами
> Библиотеки — «готовые детали конструктора»: не пишите Гаусса вручную — вызовите `solve()`, внутри которого отлаженный LAPACK.

### Преимущества библиотек

| Преимущество       | Суть                           |
| ------------------ | ------------------------------ |
| Надёжность         | отлажены на тысячах задач      |
| Производительность | оптимизированы под архитектуры |
| Переносимость      | работают на разных платформах  |
| Экономия времени   | не изобретать велосипед        |

## 4. Пакеты прикладных программ

### Определение

**Формулировка (учебник):** пакет прикладных программ (ППП) — комплекс взаимосвязанных программ, объединённых общей тематикой и предназначенных для решения задач определённого класса, как правило, с развитым пользовательским интерфейсом.

### Основные ППП математического моделирования

| ППП                      | Особенности                    | Область                    |
| ------------------------ | ------------------------------ | -------------------------- |
| **MATLAB**               | матричные вычисления, тулбоксы | научные расчёты, инженерия |
| **Mathematica**          | символьные + численные         | математика, физика         |
| **Maple**                | символьные вычисления          | математика                 |
| **Python + NumPy/SciPy** | открытый, гибкий               | наука, инженерия, ML       |
| **Julia**                | высокая скорость + простота    | научные вычисления         |
| **R**                    | статистика                     | анализ данных              |
| **GNU Octave**           | открытый аналог MATLAB         | численные расчёты          |

### Проблемно-ориентированные ППП

| Область                      | ППП                            |
| ---------------------------- | ------------------------------ |
| Гидродинамика (CFD)          | ANSYS Fluent, OpenFOAM, COMSOL |
| Механика деформируемого тела | ANSYS Mechanical, ABAQUS       |
| Электроника                  | SPICE, LTspice                 |
| Оптика                       | Zemax, COMSOL Wave Optics      |
| Молекулярная динамика        | GROMACS, LAMMPS                |

### Структура типичного ППП

$$
\text{ППП} = \text{интерфейс} + \text{библиотеки методов} + \text{визуализация} + \text{документация}
$$

> [!tip] Простыми словами
> ППП — «всё в одном»: вводишь модель, получаешь результат с графиками. Библиотеки — «конструктор»: собираешь свою программу из готовых блоков.

## 5. Сравнение: библиотеки vs пакеты

| Критерий            | Библиотеки                   | Пакеты                 |
| ------------------- | ---------------------------- | ---------------------- |
| Форма использования | встраивание в свой код       | самостоятельный запуск |
| Гибкость            | высокая                      | ограничена интерфейсом |
| Порог входа         | выше (нужно программировать) | ниже (часто GUI)       |
| Производительность  | можно оптимизировать         | как есть               |
| Пример              | LAPACK, NumPy                | MATLAB, COMSOL         |

### Когда что использовать

| Ситуация                               | Выбор                                |
| -------------------------------------- | ------------------------------------ |
| Быстрый прототип, интерактивный расчёт | ППП (MATLAB, Python)                 |
| Встраивание в большую программу        | Библиотеки (LAPACK, MKL)             |
| Высокопроизводительные расчёты         | Библиотеки + параллельные технологии |
| Обучение, демонстрация                 | ППП с визуализацией                  |

> [!important] На экзамене
> Современная практика часто комбинированная: прототип в ППП (Python/MATLAB), а тяжёлые ядра — в виде библиотек на C++/Fortran, вызываемых из высокоуровневой среды.

## 6. Примеры в контексте численных методов

### Решение СЛАУ ([[38-СЛАУ-численные-методы|Вопрос 38]])

```python
import numpy as np
# Метод Гаусса не пишем вручную — используем LAPACK через NumPy
x = np.linalg.solve(A, b)
```

### Разностная схема теплопроводности ([[46-Разностные-методы-решения-нестационарных-задач-математической-физики|Вопрос 46]])

```python
import numpy as np
N = 100
h = 1.0 / N
tau = 0.4 * h**2
sigma = tau / h**2

u = np.zeros(N+1)
u[0], u[N] = 0, 0  # граничные условия

for n in range(1000):
    u_new = u.copy()
    u_new[1:N] = (1 - 2*sigma)*u[1:N] + sigma*(u[0:N-1] + u[2:N+1])
    u = u_new
```

### Интегрирование ОДУ ([[40-Численные-методы-решения-задачи-Коши-для-систем-ОДУ|Вопрос 40]])

```python
from scipy.integrate import solve_ivp

def rhs(t, y):
    return [y[1], -y[0]]   # y'' = -y

sol = solve_ivp(rhs, [0, 10], [1, 0], method='RK45')
```

> [!tip] Простыми словами
> Численные методы «под капотом» библиотек и пакетов: вы вызываете `solve_ivp`, а внутри работает метод Рунге–Кутты, реализованный и отлаженный авторами SciPy.

## 7. Верификация и валидация

### Определения

**Формулировка (учебник):**

- **верификация** — проверка корректности реализации модели («правильно ли мы решили уравнения?»);
- **валидация** — проверка соответствия модели реальности («те ли уравнения мы решили?»).

| Этап        | Вопрос                       | Как проверяется                                 |
| ----------- | ---------------------------- | ----------------------------------------------- |
| Верификация | код решает модель правильно? | тесты на аналитических решениях, сгущение сеток |
| Валидация   | модель адекватна задаче?     | сравнение с экспериментом                       |

> [!important] На экзамене
> Любое ППО моделирования требует верификации и валидации. Без них результаты расчётов не заслуживают доверия.

## 8. Типичные ошибки на экзамене

> [!failure] Частые ошибки
> Путать **библиотеку** (встраивается в код) и **пакет** (самостоятельный инструмент).
> Считать MATLAB «языком программирования» — это среда с собственным языком, но прежде всего ППП.
> Не различать символьные (Mathematica, SymPy) и численные (LAPACK, SciPy) системы.
> Забывать про верификацию и валидацию ППО моделирования.
> Утверждать, что открытое ПО всегда хуже коммерческого — OpenFOAM, NumPy широко используются в индустрии.
> Не приводить конкретных примеров библиотек и пакетов.
> Путать системное ПО и прикладное ПО моделирования.

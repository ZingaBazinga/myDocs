# Вопрос 50. Основы объектно-ориентированного программирования. Инкапсуляция, наследование, полиморфизм

← [[00-MOC-Aspirantura-Prep]] · Предыдущий: [[49-Выражения-операции-операторы]] · Программа: [[Вопросы]]

## Краткий ответ (для устного экзамена)

> [!abstract] Простыми словами — вся суть
> **ООП** — парадигма программирования, в которой программа строится из **объектов**, объединяющих данные и методы работы с ними.
> **Класс** — шаблон (чертёж) для создания объектов; **объект** — экземпляр класса.
> **Три кита ООП:**
>
> 1. **Инкапсуляция** — объединение данных и методов + сокрытие внутренней реализации (public/private/protected).
> 2. **Наследование** — создание нового класса на основе существующего с расширением/переопределением.
> 3. **Полиморфизм** — один интерфейс, разные реализации; виртуальные функции в C++, утиная типизация в Python.
>    Плюс **абстракция** — выделение существенных свойств и игнорирование деталей.
>    В C++: `class`, `virtual`, `override`; в Python: `class`, наследование, магические методы.
>    В матмоделировании ООП позволяет строить иерархии: `РазностнаяСхема` → `ЯвнаяСхема`, `НеявнаяСхема`, `КранкНиколсон`.

## 1. Понятие объектно-ориентированного программирования

### Определение

**Формулировка (учебник):** объектно-ориентированное программирование (ООП) — парадигма программирования, в которой программа представляется как совокупность взаимодействующих **объектов**, каждый из которых является экземпляром определённого **класса**, а классы образуют иерархию наследования.

### Основные принципы

| Принцип          | Суть                                                  |
| ---------------- | ----------------------------------------------------- |
| **Абстракция**   | выделение существенных свойств, игнорирование деталей |
| **Инкапсуляция** | объединение данных и методов + сокрытие реализации    |
| **Наследование** | создание новых классов на основе существующих         |
| **Полиморфизм**  | один интерфейс — много реализаций                     |

> [!tip] Простыми словами
> ООП — это способ организовать код вокруг «вещей» (объектов), а не только функций и данных. Каждый объект знает, что он собой представляет и что умеет делать.

## 2. Классы и объекты

### Класс

**Формулировка (учебник):** класс — пользовательский тип данных, объединяющий поля (данные) и методы (функции) для работы с этими данными.

### Объект

**Формулировка (учебник):** объект (экземпляр класса) — конкретная сущность, созданная по шаблону класса, имеющая собственное состояние (значения полей).

### Пример

**C++:**

```cpp
class Point {
private:
    double x, y;           // поля (данные)
public:
    Point(double x0, double y0) : x(x0), y(y0) {}  // конструктор
    double getX() const { return x; }               // метод
    double distanceTo(const Point& other) const;    // метод
};

Point p1(1.0, 2.0);       // объект p1 класса Point
Point p2(3.0, 4.0);       // объект p2 класса Point
```

**Python:**

```python
class Point:
    def __init__(self, x, y):   # конструктор
        self.x = x              # поля
        self.y = y

    def distance_to(self, other):  # метод
        return ((self.x - other.x)**2 + (self.y - other.y)**2) ** 0.5

p1 = Point(1.0, 2.0)      # объект
p2 = Point(3.0, 4.0)      # объект
```

### Компоненты класса

| Компонент       | Назначение            | Пример           |
| --------------- | --------------------- | ---------------- |
| Поля (атрибуты) | данные объекта        | `x`, `y`         |
| Конструктор     | инициализация объекта | `Point(1, 2)`    |
| Методы          | операции над данными  | `distance_to()`  |
| Деструктор      | освобождение ресурсов | `~Point()` (C++) |

> [!tip] Простыми словами
> Класс — это «чертёж дома», объект — «конкретный построенный дом». По одному чертежу можно построить много домов (объектов).

## 3. Инкапсуляция

### Определение

**Формулировка (учебник):** инкапсуляция — механизм объединения данных и методов, работающих с этими данными, в единую сущность (класс), а также сокрытие внутренней реализации от внешнего доступа.

### Две стороны инкапсуляции

| Аспект          | Суть                                                  |
| --------------- | ----------------------------------------------------- |
| **Объединение** | данные и методы в одном классе                        |
| **Сокрытие**    | защита внутреннего состояния от некорректного доступа |

### Модификаторы доступа

| Модификатор | Доступ из класса | Доступ из наследников | Доступ извне |
| ----------- | ---------------- | --------------------- | ------------ |
| `public`    | ✅               | ✅                    | ✅           |
| `protected` | ✅               | ✅                    | ❌           |
| `private`   | ✅               | ❌                    | ❌           |

**C++:**

```cpp
class Solver {
private:
    double* u;          // скрыто от всех
    int N;              // скрыто от всех
protected:
    double tau;         // доступно наследникам
public:
    void solve();       // доступно всем
};
```

**Python:** (соглашения)

```python
class Solver:
    def __init__(self):
        self.u = []        # публичный атрибут
        self._N = 100      # защищённый (по соглашению)
        self.__tau = 0.01  # «приватный» (name mangling)
```

### Геттеры и сеттеры

**Формулировка (учебник):** для контролируемого доступа к приватным полям предоставляют специальные методы:

- **геттер** (getter) — получение значения;
- **сеттер** (setter) — изменение значения с проверкой.

```cpp
double getTau() const { return tau; }
void setTau(double t) {
    if (t > 0) tau = t;   // защита от некорректного значения
}
```

> [!tip] Простыми словами
> Инкапсуляция — «капсула»: внутри всё спрятано, снаружи — только кнопки (публичные методы). Пользователь нажимает кнопки, не зная, как всё устроено внутри.

> [!important] На экзамене
> Инкапсуляция ≠ сокрытие. Инкапсуляция — объединение + сокрытие. Сокрытие — часть инкапсуляции, но не вся она.

## 4. Наследование

### Определение

**Формулировка (учебник):** наследование — механизм создания нового класса (производного) на основе существующего (базового), при котором производный класс наследует поля и методы базового и может их расширять или переопределять.

### Терминология

| Термин            | Синонимы                 | Суть                   |
| ----------------- | ------------------------ | ---------------------- |
| Базовый класс     | родительский, суперкласс | тот, от кого наследуют |
| Производный класс | дочерний, подкласс       | тот, кто наследует     |

### Пример

**C++:**

```cpp
class DifferenceScheme {          // базовый класс
protected:
    double h, tau;
    int N;
public:
    DifferenceScheme(double h0, double tau0) : h(h0), tau(tau0) {}
    virtual void solve() = 0;     // чисто виртуальный метод
};

class ExplicitScheme : public DifferenceScheme {   // производный
public:
    ExplicitScheme(double h, double tau) : DifferenceScheme(h, tau) {}
    void solve() override { /* реализация явной схемы */ }
};

class ImplicitScheme : public DifferenceScheme {   // производный
public:
    ImplicitScheme(double h, double tau) : DifferenceScheme(h, tau) {}
    void solve() override { /* реализация неявной схемы */ }
};
```

**Python:**

```python
class DifferenceScheme:
    def __init__(self, h, tau):
        self.h = h
        self.tau = tau

    def solve(self):
        raise NotImplementedError

class ExplicitScheme(DifferenceScheme):
    def solve(self):
        # реализация явной схемы
        pass

class ImplicitScheme(DifferenceScheme):
    def solve(self):
        # реализация неявной схемы
        pass
```

### Виды наследования

| Вид            | Суть               | Пример                   |
| -------------- | ------------------ | ------------------------ |
| Одиночное      | один базовый класс | `B : A`                  |
| Множественное  | несколько базовых  | `C : A, B` (C++, Python) |
| Многоуровневое | цепочка            | `A → B → C`              |

### Переопределение методов

**Формулировка (учебник):** производный класс может заменить реализацию метода базового класса — это называется **переопределением** (override).

> [!tip] Простыми словами
> Наследование — «ребёнок получает от родителей всё, но может добавить своё или переделать». Базовый класс задаёт общий интерфейс, производные — конкретные реализации.

## 5. Полиморфизм

### Определение

**Формулировка (учебник):** полиморфизм — возможность объектов разных классов реагировать на один и тот же вызов метода по-разному, в зависимости от своего реального типа.

### Виды полиморфизма

| Вид                                     | Суть                                                              | Пример                                  |
| --------------------------------------- | ----------------------------------------------------------------- | --------------------------------------- |
| **Полиморфизм подтипов** (динамический) | вызов виртуального метода через указатель/ссылку на базовый класс | `scheme->solve()`                       |
| **Перегрузка** (статический)            | одно имя — разные сигнатуры                                       | `add(int, int)` и `add(double, double)` |
| **Параметрический**                     | шаблоны / обобщения                                               | `template<typename T>` в C++            |
| **Утиная типизация**                    | «если ведёт себя как утка — это утка»                             | Python                                  |

### Виртуальные функции в C++

**Формулировка (учебник):** виртуальная функция — метод базового класса, который может быть переопределён в производном; вызов через указатель/ссылку на базовый класс определяется реальным типом объекта во время выполнения (динамическая диспетчеризация).

```cpp
DifferenceScheme* scheme;
if (explicit) {
    scheme = new ExplicitScheme(h, tau);
} else {
    scheme = new ImplicitScheme(h, tau);
}
scheme->solve();   // вызывается нужный метод в зависимости от реального типа
```

### Утиная типизация в Python

**Формулировка (учебник):** в Python полиморфизм реализуется через утиную типизацию: тип объекта не важен, важно наличие нужных методов.

```python
def run_scheme(scheme):
    scheme.solve()   # работает с любым объектом, у которого есть метод solve()

run_scheme(ExplicitScheme(h, tau))
run_scheme(ImplicitScheme(h, tau))
```

> [!tip] Простыми словами
> Полиморфизм — «один вызов, разные действия». Вызываем `solve()`, а что именно будет сделано — зависит от того, какой объект на самом деле вызван.

### Пример с фигурами

**C++:**

```cpp
class Shape {
public:
    virtual double area() const = 0;   // абстрактный метод
};

class Circle : public Shape {
    double r;
public:
    Circle(double r0) : r(r0) {}
    double area() const override { return 3.14159 * r * r; }
};

class Rectangle : public Shape {
    double w, h;
public:
    Rectangle(double w0, double h0) : w(w0), h(h0) {}
    double area() const override { return w * h; }
};
```

> [!important] На экзамене
> Полиморфизм работает через указатель или ссылку на базовый класс. Если объект базового класса взят по значению, происходит «срезка» (slicing) — полиморфизм теряется.

## 6. Абстракция (кратко)

### Определение

**Формулировка (учебник):** абстракция — выделение существенных характеристик объекта и игнорирование несущественных деталей реализации.

### Пример

Для разностной схемы существенны: шаги $h$, $\tau$, метод `solve()`. Несущественны: как именно хранятся массивы, какой язык используется внутри.

### Абстрактные классы

**Формулировка (учебник):** абстрактный класс — класс, содержащий хотя бы один чисто виртуальный метод (C++) или метод, не имеющий реализации. Экземпляры абстрактного класса создать нельзя.

```cpp
class DifferenceScheme {
public:
    virtual void solve() = 0;   // чисто виртуальный → класс абстрактный
};
```

> [!tip] Простыми словами
> Абстракция — «чертёж без деталей»: знаем, что схема умеет решать, но не знаем как именно. Конкретика — в производных классах.

## 7. Сравнение трёх китов ООП

| Принцип      | Что делает                       | Ключевые слова (C++)             | Ключевые слова (Python)             |
| ------------ | -------------------------------- | -------------------------------- | ----------------------------------- |
| Инкапсуляция | объединяет и скрывает            | `private`, `protected`, `public` | `_`, `__`, свойства                 |
| Наследование | создаёт иерархию                 | `class B : public A`             | `class B(A):`                       |
| Полиморфизм  | один интерфейс, много реализаций | `virtual`, `override`            | утиная типизация, `@abstractmethod` |

## 8. Применение в математическом моделировании

### Иерархия разностных схем

Используя ООП, можно построить иерархию классов для [[46-Разностные-методы-решения-нестационарных-задач-математической-физики|Вопроса 46]]:

```
DifferenceScheme (абстрактный)
├── ExplicitScheme       — явная схема теплопроводности
├── ImplicitScheme       — неявная схема
├── CrankNicolsonScheme  — схема Кранка–Николсон
└── WaveScheme           — схема для волнового уравнения
```

### Преимущества ООП в численных методах

| Преимущество            | Пример                                                   |
| ----------------------- | -------------------------------------------------------- |
| Повторное использование | базовый класс сетки используется во всех схемах          |
| Расширяемость           | новая схема добавляется как производный класс            |
| Инкапсуляция деталей    | пользователь вызывает `solve()`, не зная прогонки внутри |
| Полиморфизм             | один код работает с любой схемой через базовый указатель |

> [!tip] Простыми словами
> ООП позволяет написать «каркас» численного метода один раз, а конкретные схемы добавлять как наследников. Это основа библиотек и комплексов программ.

## 9. Типичные ошибки на экзамене

> [!failure] Частые ошибки
> Путать **класс** (тип/шаблон) и **объект** (экземпляр).
> Считать инкапсуляцию только «сокрытием» — она также включает объединение данных и методов.
> Путать **перегрузку** (overload) и **переопределение** (override): перегрузка — одно имя, разные сигнатуры в одном классе; переопределение — замена метода базового класса в производном.
> Забывать ключевое слово `virtual` в C++ — без него полиморфизм через указатель на базовый класс не работает.
> Не помнить про деструктор: в C++ при наследовании деструктор базового класса должен быть виртуальным.
> Считать, что в Python есть строгие `private` — там только соглашения (`_`, `__`).
> Путать абстрактный класс и интерфейс (в C++ абстрактный класс с чисто виртуальными методами играет роль интерфейса).
> Не приводить примеры из конкретных языков.

> 5. **Полиморфизм:**
>     - виртуальные функции: `virtual void solve() = 0;`
>     - вызов через указатель на базовый класс;
>     - утиная типизация в Python.
> 6. **Абстракция** — выделение существенного; абстрактный класс.
> 7. **Пример из ЧМ:** иерархия разностных схем `DifferenceScheme → ExplicitScheme, ImplicitScheme`.

### Чеклист устно / письменно

| Тема         | Устно                           | Письменно                   |
| ------------ | ------------------------------- | --------------------------- |
| ООП          | «объекты = данные + методы»     | определение                 |
| Класс/объект | «чертёж/дом»                    | определение + пример кода   |
| Инкапсуляция | «объединение + сокрытие»        | модификаторы доступа        |
| Наследование | «новый класс из базового»       | пример `class B : A`        |
| Полиморфизм  | «один вызов, разные реализации» | `virtual`, утиная типизация |
| Абстракция   | «существенное, без деталей»     | абстрактный класс           |
| Пример из ЧМ | иерархия схем                   | диаграмма наследования      |

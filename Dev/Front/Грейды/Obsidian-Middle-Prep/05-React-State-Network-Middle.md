# React (глубина), State Management, Сеть — Middle

Стек из матрицы: React, TanStack Router/Start. Подстраивай формулировки под ваш проект.

---

## Виртуальный DOM и reconciliation

React держит дерево Fiber; при обновлении сравнивает новое дерево со старым (**diffing**), группирует эффекты, поддерживает приоритеты (Concurrent).

На собеседовании: «Не перерисовывает «весь DOM» целиком — вычисляет минимальный набор изменений; Fiber позволяет прерывать и возобновлять работу».

---

## Порталы `createPortal`

Рендер дочерних узлов в другой DOM-узел (часто `document.body`) — модалки, тултипы, чтобы не ломать позиционирование и z-index контейнеров.

---

## Error Boundaries

Класс-компонент с **`componentDidCatch`** или **`getDerivedStateFromError`** (или будущие аналоги в функциональном стиле где поддержано). Ловят ошибки **рендера** дочерних, не ловят асинхронные ошибки в обработчиках без обёртки.

Стратегия: fallback UI, логирование в Sentry, изоляция частей приложения.

---

## memo, useMemo, useCallback

- **`React.memo`** — пропускает ре-рендер при тех же props (поверхностное сравнение; можно свой comparator).
- **`useMemo`** — мемоизация вычисления значения.
- **`useCallback`** — мемоизация функции (часто чтобы стабильная ссылка для memo-детей).

**Когда не стоит:** преждевременная оптимизация усложняет код; профилируй сначала.

---

## useReducer

Локальный «редьюсер» для сложного состояния с несколькими поддействиями; предсказуемость как в Redux на уровне компонента.

---

## useId, useDeferredValue, useTransition

- **`useId`** — стабильные уникальные id для доступности (связь label/input).
- **`useDeferredValue`** — откладывает обновление «тяжёлого» отображения (например список при быстром вводе).
- **`useTransition`** — помечает обновление как не срочное; `isPending` для индикатора.

---

## forwardRef и useImperativeHandle

Проброс ref на DOM или императивный API обёртки; **`useImperativeHandle`** ограничивает то, что родитель может вызвать (лучше по возможности декларативный API).

---

## Context API и оптимизация

Разделяй контексты по доменам — иначе любое изменение триггерит подписчиков. Паттерны: контекст только для «редко меняющихся» данных; для частых — state manager или колокация состояния.

---

## Suspense и lazy

`React.lazy(() => import('./Page'))` + `<Suspense fallback={…}>` — **code splitting** на уровне компонентов.

Ограничения: обработка ошибок через Error Boundary; для data fetching — зависит от фреймворка (RSC, Router loaders).

---

## React Server Components (концептуально)

Компоненты выполняются на сервере; на клиент не отправляется весь их JS — сериализуется результат и инструкции. Уменьшает bundle; нужна поддержка сборки (Next, TanStack Start и т.д.).

---

## Конкурентный рендеринг

Batching обновлений, **Transitions** — чтобы не блокировать ввод пользователя при тяжёлом рендере.

---

## SSR, SSG, ISR

- **SSR** — HTML на каждый запрос (динамика, персонализация).
- **SSG** — HTML на этапе сборки (скорость, CDN).
- **ISR** — пересборка по TTL/он-деманд — компромисс.

Фронт Middle должен **объяснить выбор** под задачу (SEO, TTFB, свежесть данных).

---

## Vue и Angular (база из матрицы)

Для Middle достаточно **общих представлений**, если основной стек — React.

**Vue 3:** реактивность (`ref`/`reactive`), однофайловые компоненты, Composition API, директивы (`v-if`/`v-for`), роутер Pinia/Vue Router на уровне «зачем это нужно».

**Angular:** модули/standalone-компоненты, DI, шаблоны с директивами, RxJS как основа асинхронности — достаточно понимать отличия от React (шаблон vs JSX, зона изменений).

---

## TanStack Start / Remix-подобное (из матрицы)

**Файловый роутинг**, **layout routes**, **middleware** на сервере, **API routes**, **Server Actions** — сервер как часть приложения; загрузчики данных рядом с маршрутами уменьшают водопады запросов.

Сформулируй для себя: как в вашем проекте устроены данные при переходе между страницами.

---

## State Management — паттерны

**Redux** — предсказуемый поток, экосистема; цена — бойлерплейт (срезают RTK).

**Zustand / Jotai** — минимализм; Jotai — атомы, гранулярные подписки.

Критерии: масштаб, отладка, SSR, требования к middleware.

---

## Нормализация данных

Хранить сущности по `id` (как в БД), а не вложенные деревья — меньше дублирования, проще обновления и мемоизация селекторов.

---

## Оптимистичные обновления

UI обновляется до ответа сервера; при ошибке — откат и уведомление. Нужны идемпотентные API и продуманный UX.

---

## Кэш серверного состояния: TanStack Query, SWR, Apollo

Не дублируй в Redux то, что уже кэш запросов: **stale-while-revalidate**, фоновые рефетчи, дедупликация, инвалидация по ключам.

---

## Серверное vs клиентское состояние

Серверное: данные с API (кэшируемые). Клиентское: UI (модалки, ввод в поле), прежде чем сохранить. Смешивание приводит к багам синхронизации.

---

## Finite state machines (XState)

Явные состояния и переходы вместо леса флагов `isLoading`, `isError` — полезно для сложных форм и мастеров.

---

## REST API (продвинутое)

**Версионирование** (`v1` в пути или заголовке), **пагинация** offset vs cursor (курсор лучше для живых лент), **фильтры/сортировка** как query params, единый формат ошибок.

---

## GraphQL

Запросы точечно запрашивают поля; **мутации** изменяют; **подписки** для real-time (через WS). **Фрагменты** переиспользуют куски запросов.

Клиенты **Apollo / urql** — кэш нормализованный по `__typename`+`id`.

---

## HTTP/2 и HTTP/3

**HTTP/2:** мультиплексирование в одном TCP, приоритеты потоков, server push (редко используют сейчас).

**HTTP/3 / QUIC:** UDP, меньше head-of-line blocking на нестабильных сетях.

---

## Кэширование HTTP

**`Cache-Control`** — `max-age`, `no-store`, `stale-while-revalidate`.

**`ETag`** + **`If-None-Match`** — условный запрос 304.

**`Vary`** — от чего зависит представление (например `Accept-Language`).

---

## Content-Type

**`application/json`**, **`multipart/form-data`** (файлы), **`application/x-www-form-urlencoded`** (простые формы).

---

## Rate limiting и retry

Клиент: **exponential backoff + jitter**, лимит попыток, не ретраить неидемпотентные POST без защиты (или с idempotency key).

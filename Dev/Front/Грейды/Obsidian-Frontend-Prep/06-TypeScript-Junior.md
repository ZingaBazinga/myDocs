# TypeScript — Junior

## Какие типы обязан знать Junior?

Базовые типы: `string`, `number`, `boolean`, `null`, `undefined`, `void`, `never`, `unknown`, `any`.  
На практике особое внимание:
- `unknown` безопаснее `any`
- `never` полезен для недостижимых веток и exhaustive checks

## `interface` и `type`: в чем разница?

Оба описывают структуру данных.  
Базовый подход:
- `interface` удобно расширять и мержить декларации
- `type` удобно для union/intersection и алиасов

Junior достаточно уверенно использовать оба и держать единый стиль в проекте.

## Массивы и кортежи

- массивы: `string[]`, `Array<string>`
- кортежи: `[string, number]` для фиксированного набора разных типов

## Union и intersection

- `A | B` — значение может быть одним из типов
- `A & B` — значение должно удовлетворять обоим типам

Это база для моделирования состояния и API-ответов.

## Литеральные типы и enum

Литеральные типы: `'success' | 'error'` для ограниченного набора значений.  
`enum` — именованные константы (строковые или числовые), но в современных проектах часто выбирают union литералов.

## Типизация функций

Нужно указывать:
- типы параметров
- возвращаемый тип
- опциональные параметры
- значения по умолчанию

Это помогает ловить ошибки еще до запуска кода.

## Что такое type assertion?

`value as Type` — ручное утверждение типа, когда разработчик точно знает структуру.  
Важно: assertion не делает runtime-проверку, поэтому использовать аккуратно.

## Типизация объектов

Полезные конструкции:
- `?` для опциональных полей
- `readonly` для неизменяемых свойств

## `typeof` и `keyof` на Junior

- `typeof` в типах позволяет вывести тип из значения
- `keyof` возвращает объединение ключей объекта

Это основа для безопасных универсальных функций и утилит.

# Тестирование и Soft Skills — Junior

## Тестирование: что должен уметь Junior

### Виды тестов и зачем они нужны

- **Unit** — проверка одной функции/модуля в изоляции
- **Integration** — проверка взаимодействия частей системы
- **E2E** — сценарий целиком глазами пользователя

Цель тестов — уменьшать риск регрессий, а не просто «набивать проценты покрытия».

### База Jest/Vitest

Структура теста:
- `describe` — группировка сценариев
- `it`/`test` — конкретный кейс
- `expect` — проверка результата

Минимальный набор матчеров:
`toBe`, `toEqual`, `toBeTruthy`, `toContain`, `toThrow`.

### Setup/teardown

`beforeEach`, `afterEach`, `beforeAll`, `afterAll` используют для подготовки и очистки окружения.

### Моки

- `fn()` — фейковая функция
- `mock()` — замена модуля
- `spyOn()` — слежение/подмена метода

Моки позволяют изолировать тест от сети, времени, случайности и сторонних сервисов.

### Тестирование компонентов

Через Testing Library:
1. рендер компонента
2. поиск элементов (желательно по роли/тексту)
3. имитация действий пользователя
4. проверка ожидаемого поведения в UI

## Soft skills: ожидания Junior

### Базовые ожидания команды

- выполнять задачи в срок
- заранее сообщать о блокерах
- принимать обратную связь и исправлять решение
- задавать уточняющие вопросы по требованиям
- соблюдать процессы команды (ветки, ревью, стендапы)
- писать понятные коммиты и рабочие сообщения
- вести короткие заметки по прогрессу

### Как озвучивать это на ревью

Используй схему:
**контекст -> действие -> результат**.

Пример:
«В задаче по форме регистрации я уточнил требования, разбил работу на шаги, заранее сообщил о блокере по API, закрыл задачу в срок и добавил тест на валидацию, чтобы избежать регрессии».

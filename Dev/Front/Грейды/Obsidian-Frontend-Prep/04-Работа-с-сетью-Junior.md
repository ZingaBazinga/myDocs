# Работа с сетью — Junior

## HTTP: что важно объяснить на Junior?

HTTP — протокол запрос/ответ между клиентом и сервером.

Основные методы:
- `GET` — получить данные
- `POST` — создать
- `PUT` — полностью обновить
- `PATCH` — частично обновить
- `DELETE` — удалить

Классы кодов ответа:
- `2xx` — успех
- `3xx` — редиректы
- `4xx` — проблема на стороне клиента
- `5xx` — проблема на стороне сервера

## `fetch()` API: как правильно использовать?

Типовой алгоритм:
1. отправить запрос с методом, заголовками и телом (если нужно)
2. проверить `response.ok`
3. прочитать тело через `.json()`, `.text()` или `.blob()`
4. обработать ошибки сети через `try/catch`

Важно: HTTP-ошибка (например 404) сама по себе не бросает исключение в `fetch`.

## REST базово

REST подразумевает работу с ресурсами через эндпоинты (`/users`, `/orders`) и HTTP-методы как CRUD-операции.  
Junior должен понимать логику ресурса и не смешивать действия в одном endpoint без необходимости.

## CORS простыми словами

CORS — политика браузера для cross-origin запросов.  
Если сервер не вернул нужные `Access-Control-Allow-*` заголовки, браузер не даст фронту прочитать ответ.

Ключевые понятия:
- simple request
- preflight (`OPTIONS`) для «непростых» запросов

## JSON как формат обмена

JSON — стандарт API-обмена в вебе.  
Сериализация: `JSON.stringify`, десериализация: `JSON.parse`.

## DNS, TCP/IP, HTTPS — минимальная база

- DNS преобразует домен в IP
- TCP обеспечивает надежную доставку
- HTTPS шифрует трафик через TLS

Этого уровня хватает, чтобы понимать, где искать проблемы сети.

## Cookies: что нужно знать на Junior?

Cookie — данные, которые браузер хранит и может отправлять с запросом.  
Ключевые атрибуты:
- `HttpOnly` — недоступно через JS
- `Secure` — только по HTTPS
- `SameSite` — ограничивает cross-site отправку (важно для CSRF)
